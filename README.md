# MMA3001 Project — Golf Ball Outcome Prediction

## Project Overview

This project investigates whether machine-learning models can predict golf ball outcomes from golf swing and ball-strike measurements.

The dataset contains golf shot measurements obtained using a **TrackMan system**. These measurements describe swing characteristics and ball launch conditions and are used to investigate how a golf swing relates to the ball's final position.

The project establishes a linear regression baseline and then trains a multi-output neural network to predict two outcomes:

- **Side Total** — the lateral component of the ball's final position.
- **Total** — the total-distance component of the ball's final position.

## Repository Structure

- `data files/` — The original TrackMan dataset, cleaned data, and generated training and validation datasets.
- `Code files/` — Data preparation, regression, neural-network and pytest scripts.
- `Main.py` — Runs the primary workflow and displays saved model graphs when launched within a notebook kernel.
- `model outputs/` — Created at runtime to store PNG evaluation graphs (the directory need not exist beforehand).
- `docs/source_documentation.html` — Browsable HTML source documentation.

## Required Execution Order

**Recommended:** Run `Main.py` to execute the three primary scripts in order. Each modelling script relies on the datasets generated by the data-processing script. You can also run each script individually.

### 1. `Data_processing.py` — Prepare the Data

This script prepares the original dataset for modelling. It:

- Loads `data files/data.csv`.
- Skips the row containing measurement units.
- Removes the `Ball`, `Dynamic Lie`, `Impact Offset`, and `Impact Height` columns.
- Retains shots recorded with the Driver.
- Removes rows containing missing values.
- Saves the cleaned dataset as `data files/cleaned_data.csv`.
- Generates separate training and validation datasets.

The two files used by the modelling scripts are:

- `data files/Training data.csv`
- `data files/Validation data.csv`

Run this script first whenever you need to regenerate the processed datasets from the original data.

### 2. `linear_regression_side_total.py` — Establish the Baseline

This script trains a linear regression model to predict **Side Total**. It:

- Loads the training and validation datasets.
- Selects five input features using statistical feature selection.
- Fits a linear regression model using the selected features.
- Evaluates the model on both training and validation data.
- Reports Mean Absolute Error (MAE) and the coefficient of determination (`R²`).
- Saves actual-versus-predicted plots for both datasets as `model outputs/linear_regression_training.png` and `model outputs/linear_regression_validation.png`.

The validation results provide a baseline against which future models can be compared. This helps assess whether a more complex model improves prediction performance.

### 3. `NN_Combined.py` — Train the Neural Network

This script trains a multi-output neural network to predict both **Side Total** and **Total**. It:

- Loads the training and validation datasets.
- Uses 15 golf swing and ball-strike measurements as input features.
- Standardises the input features.
- Trains a neural network with two hidden layers, each containing 500 neurons.
- Predicts both target variables simultaneously.
- Trains for 150 epochs using the Adam optimiser and mean squared error (MSE) loss.
- Reports training and validation loss during training.
- Saves actual-versus-predicted plots for both targets (with MAE and R² in the titles) as `model outputs/nn_combined_side_total.png` and `model outputs/nn_combined_total.png`.
- Uses a `main()` function so documentation and tests can import the model class without starting training.

Compare the neural network's validation results with the baseline results, keeping in mind that the baseline currently predicts Side Total only, while the neural network predicts both Side Total and Total.

## Automated Tests

`Code files/Test_NN_Combined.py` contains four pytest checks:

1. Input features exclude the two prediction targets.
2. The neural network returns two outputs per shot.
3. Feature scaling is fitted only to training data.
4. A training step produces a finite loss and updates model parameters.

The tests use small synthetic datasets and do not run the full 150-epoch training workflow. They complement, rather than replace, validation metrics.

Run from the repository root:

```bash
python -m pytest "Code files/Test_NN_Combined.py" -v
```

You can also run the file directly, including in Colab:

```bash
python "Code files/Test_NN_Combined.py"
```

2. Attack Angle

7. Dynamic Loft
8. Face Angle
9. Face To Path
10. Ball Speed
11. Smash Factor
12. Launch Angle
13. Launch Direction
14. Spin Rate
15. Spin Axis

## Evaluation Metrics

- **Mean Absolute Error (MAE):** The average absolute difference between predicted and actual values. Lower values indicate smaller average errors.
- **Coefficient of determination (R²):** Indicates how well predictions explain variation in the target values. A value closer to 1 generally indicates a better fit; a negative value indicates performance worse than predicting the target mean on the evaluated dataset.
- **Mean Squared Error (MSE):** The average squared prediction error. The neural network uses MSE as its training loss and reports it for the training and validation datasets.

Validation metrics are particularly useful for comparing models because the validation data is not used to fit the model parameters.

## Running the Project

Run the complete workflow from the repository root:

```bash
python Main.py
```

Or run the scripts individually in the required order:

```bash
python "Code files/Data_processing.py"
python "Code files/linear_regression_side_total.py"
python "Code files/NN_Combined.py"
```

`Main.py` streams printed output from each child script, saves the four graphs in `model outputs/`, and attempts to display them inline when run inside a Jupyter/Colab kernel. In Google Colab, use `%run "/content/MMA3001-Project/Main.py"` after pulling the latest repository changes; using `!python` still saves the graphs but does not display them inline through the parent notebook kernel.

The data-processing and modelling scripts resolve the data directory relative to each script's location. You do not need to launch Python from the repository root or store the repository at a particular absolute path. The repository must contain the expected `data files/` and `Code files/` folders, and the generated training and validation datasets must exist before running the modelling scripts.

## Project Objective

The overall objective is to establish a reproducible data-processing workflow, measure the performance of a simple regression model, and investigate whether a neural network can improve predictions of golf ball final position using TrackMan swing and ball-strike measurements.
